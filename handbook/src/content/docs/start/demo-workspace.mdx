The field guide uses three sibling repositories so the screenshots and
walkthroughs can demonstrate a real fleet rather than a contrived hello-world.
Together they cover Go, Java, Python, JavaScript, SQL, Maven, Kubernetes,
Docker Compose, HTTP, messaging, service discovery, PostgreSQL, SQLite, and MCP.

## Reproducible layout

```text
~/Developer/
├── RepoKarta/
├── spring-petclinic-microservices/
└── bank-of-anthos/
```

| System | Role in the guide | Captured revision |
| --- | --- | --- |
| RepoKarta | Go product, browser UI, MCP, storage, indexing | recorded by `capture-manifest.json` |
| Spring Petclinic Microservices | Java service discovery, REST, Maven, Compose | `305a1f13e4f961001d4e6cb50a9db51dc3fc5967` |
| Bank of Anthos | Python + Java + Kubernetes + PostgreSQL | `1e40564f9ff572a28281198903e19da93e506770` |

## Start the catalogue

<Steps>
1. Clone the three systems into one workspace.

   <Tabs>
     <TabItem label="macOS / Linux">
       ```sh
       mkdir -p "$HOME/Developer"
       cd "$HOME/Developer"
       git clone https://github.com/spolnik/RepoKarta.git
       git clone https://github.com/spring-petclinic/spring-petclinic-microservices.git
       git clone https://github.com/GoogleCloudPlatform/bank-of-anthos.git
       ```
     </TabItem>
     <TabItem label="Windows PowerShell">
       ```powershell
       New-Item -ItemType Directory -Force "$HOME\Developer" | Out-Null
       Set-Location "$HOME\Developer"
       git clone https://github.com/spolnik/RepoKarta.git
       git clone https://github.com/spring-petclinic/spring-petclinic-microservices.git
       git clone https://github.com/GoogleCloudPlatform/bank-of-anthos.git
       ```
     </TabItem>
   </Tabs>

2. Build RepoKarta’s browser assets.

   <Tabs>
     <TabItem label="macOS / Linux">
       ```sh
       cd "$HOME/Developer/RepoKarta"
       npm --userconfig .npmrc --prefix web ci
       npm --prefix web run build
       ```
     </TabItem>
     <TabItem label="Windows PowerShell">
       ```powershell
       Set-Location "$HOME\Developer\RepoKarta"
       npm --userconfig .npmrc --prefix web ci
       npm --prefix web run build
       ```
     </TabItem>
   </Tabs>

3. Launch RepoKarta against the workspace, not a user-specific absolute path.

   <Tabs>
     <TabItem label="macOS / Linux">
       ```sh
       go run ./cmd/repokarta serve -open=false "$HOME/Developer"
       ```
     </TabItem>
     <TabItem label="Windows PowerShell">
       ```powershell
       go run ./cmd/repokarta serve -open=false "$HOME\Developer"
       ```
     </TabItem>
   </Tabs>

4. Open `http://127.0.0.1:7331`. The repository drawer reports indexing state
   per repository; Search can become useful before every secondary artifact is
   complete.
</Steps>

## Why these examples matter

| Question | Best example |
| --- | --- |
| Where is a Spring endpoint implemented and who calls it? | `OwnerResource` in Petclinic |
| Does a package import imply a running service call? | compare Petclinic maps with topology |
| How does configuration resolve a service target? | Bank of Anthos Kubernetes environment |
| What is compiler-precise versus syntax-backed? | Petclinic with and without Java SCIP |
| How are browser and agent answers kept consistent? | RepoKarta’s HTTP, Chat, and MCP layers |

<Aside type="note" title="Every product visual is a real local capture">
	The capture command builds an isolated RepoKarta binary, uses a separate data
	directory, verifies the three pinned repositories, and records Chromium. No
	product screen is redrawn for the handbook.
</Aside>
