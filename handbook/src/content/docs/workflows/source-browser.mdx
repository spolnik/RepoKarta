bounded repository tree, focused line ranges, symbol intelligence, detected
routes, and Git history while keeping a copyable citation visible. This
demonstration opens the Java controller at its matching lines and keeps the
repository tree, route facts, and revision in view.

## Investigation pattern

<Steps>
1. Open the matching source range from Search, Maps, Dependencies, or a citation.
2. Confirm repository, commit, path, and line range before reading the code.
3. Enter an identifier and choose the evidence class you need: definition,
   references, implementations, routes, or callers.
4. Read the provider label. `SCIP` and `syntax-backed` are materially different.
5. Use Git history to ask when and why the code changed; use diff to inspect the
   actual patch between resolved revisions.
6. Copy the citation only after the relevant line is in focus.
</Steps>

## Java SCIP

Java semantic indexing is optional background work. `off` disables generation,
`auto` preserves ordinary indexing when generation cannot run, and `required`
makes missing or failed compiler support a hard configuration failure.
RepoKarta records readiness, chosen JDK, failure category, and retry state; it
does not silently label AST fallback as compiler precision.

<Aside type="caution" title="No references is not proof of dead code">
	Dependency injection, reflection, framework configuration, generated code,
	profiles, and incomplete compiler coverage can hide valid reachability. Treat
	an empty result in the context of provider and completeness metadata.
</Aside>
