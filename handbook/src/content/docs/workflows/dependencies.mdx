Dependencies combines a revision-pinned software inventory with service-call
evidence and a separately refreshed advisory snapshot. It answers “what is
declared?”, “what version was resolved?”, “where is it declared?”, and “what
did the last OSV snapshot say?” without executing the project.

## Advisories and SARIF

<Steps>
1. Select one repository or a permission-checked context.
2. Confirm the dependency snapshot is ready and inspect unresolved-versus-
   declared version confidence.
3. Check advisory snapshot state and age before treating “no findings” as
   current.
4. Filter by ecosystem, package, advisory, or severity and open the cited
   manifest line.
5. Export SARIF when another review surface needs the same finding set.
</Steps>

Findings are de-duplicated by advisory, repository, package, and resolved
version. A resolved lockfile version takes precedence. A declared-only match is
retained with lower confidence rather than discarded or presented as exact.

<Aside type="caution" title="Unavailable is not clean">
	If the advisory snapshot is unavailable or stale, the correct conclusion is
	that vulnerability status is unknown for that snapshot—not that the
	dependency is safe.
</Aside>
